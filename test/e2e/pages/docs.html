Recovering a paused delivery queue

A delivery queue pauses after repeated destination failures so that one unavailable endpoint cannot consume all worker capacity. Before resuming it, confirm whether the destination has recovered and preserve a sample failed request for diagnosis.

Inspect the pause reason

Open the queue details and compare the recorded status codes with recent destination logs. Authentication failures require corrected credentials, while timeout clusters usually indicate capacity or network problems.

Test a single delivery

Send one stored event through the test action. The action uses the current configuration but does not advance the production cursor, making it safe to repeat while validating headers and response bodies.

Resume processing

Resume at the oldest retained event and watch the error rate for several minutes. If failures return, pause the queue again rather than allowing automatic retries to amplify pressure on the destination.
